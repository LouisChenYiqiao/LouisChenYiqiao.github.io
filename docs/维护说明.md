# 维护说明

## 网站结构

网站使用原生 HTML、CSS 和 JavaScript，无框架及构建依赖。GitHub Pages 从 `main` 分支根目录发布，实际地址见仓库的 **Settings → Pages**。

```text
.
├── index.html
├── assets/
│   ├── css/style.css
│   ├── js/site.js
│   └── images/
│       ├── sunset-walk.jpeg
│       └── favicon.svg
├── scripts/deploy.sh
└── docs/
```

首页包括首屏、关于我、日常与创作三个区块，锚点分别为 `top`、`about`、`notes`。导航和按钮应指向现有锚点。

## 内容维护

- 文字在 `index.html` 中修改，网站使用昵称 LouisQiao。
- 样式在 `assets/css/style.css` 中修改，首屏图片由 `.hero-bg` 引用。
- 小型交互在 `assets/js/site.js` 中维护，目前包括页脚年份和滚动导航效果。
- 新增图片前检查 EXIF、GPS、作者及设备等元数据；文件名使用内容描述。
- 当前首页不提供联系方式，也不发布含个人联系地址的 `security.txt`。

## 本地预览

在仓库根目录运行：

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

浏览器访问 `http://127.0.0.1:8000`，检查桌面和移动宽度下的布局、锚点与资源加载。

## 发布

修改并提交后，将 `main` 分支推送到当前仓库的 `origin`。GitHub Pages 完成构建后，检查公开页面及静态资源。

也可使用现有部署脚本：

```bash
./scripts/deploy.sh "更新主页内容"
```

脚本从仓库上一级的 `secrets/github.token` 读取部署凭据，通过临时 `GIT_ASKPASS` 提交给 Git。凭据不可写入源码、远端 URL、命令参数或日志。

脚本会检查远端 `main` 是否含有尚未同步的提交。若检查失败，应先处理差异；不要强制推送覆盖远端内容。

## 隐私与安全

- 发布前检查 HTML、注释、样式、脚本、图片元数据、文档和其他可直接下载的文件。
- 对外源码不写入真实姓名、私人联系方式、学校、所在地、本机绝对路径或带身份线索的账号地址。
- 仓库历史、账号资料和搜索缓存不随当前文件修改而自动清除，须单独评估。
- 页面 CSP 只允许本站的脚本、样式和图片。新增外部资源时应复核该策略。
- 页面设置 Referrer Policy；不嵌入第三方统计、表单或管理入口。
- 本地工具状态目录与凭据应加入 `.gitignore`，避免被部署脚本暂存。

## 常见问题

- **404**：检查仓库 Settings → Pages 是否选择 `main` 分支及根目录，并确认存在 `index.html`。
- **更新未生效**：确认提交已推送，查看 Pages 构建结果，再使用无痕窗口检查。
- **图片不显示**：确认文件已提交，并检查引用路径、大小写及文件名。
